# Notifyi 하드웨어 연결

## 현재 구현 기준

현재 Python 프로그램은 Dynamixel SDK로 직렬 버스에 직접 연결한다. 삼성 노트북과 OpenCR는 USB로 연결되며, OpenCR에는 `usb_to_dxl` 브리지 펌웨어가 올라간 구성이다. 즉, ROS 2나 별도의 OpenCR 명령 프로토콜이 아니라 **OpenCR를 직렬 브리지로 사용**한다.

현재 설정:

- 포트: /dev/ttyACM0
- Baudrate: 57600
- Protocol: 2.0
- 모델: 2XL430-W250
- 전체 ID: 1부터 8
- 설정상 구동 ID: 2, 3, 4, 5, 6, 7 (ID 1·8은 유휴)

## 논리 연결

~~~text
상위 컴퓨터
  ├─ USB 카메라 또는 로봇 탑재 카메라
  └─ USB → OpenCR (`usb_to_dxl` 브리지)
       └─ TTL 3핀 Dynamixel 버스 → ID 1 ... ID 8

외부 전원(현재 12V 구성)
  └─ OpenCR/모터 전원 경로 — 실제 배선·전압 측정으로 확인
~~~

이는 현재 `config/robot.yaml`과 스캔 기록의 연결 구조다. 물리 데이지체인 순서, 전원 분배, 퓨즈/차단기 및 한 2XL 하우징에 들어 있는 ID 쌍은 아직 현장 기록이 필요하다. TTL 포트 3개는 같은 버스이며 각 포트가 별도 ID를 뜻하지 않는다. 상세 핀·전원 경계는 [OPENCR_IO_MAP.md](OPENCR_IO_MAP.md)를 따른다.

## OpenCR을 사용할 때

현재 OpenCR는 USB-직렬 ↔ Dynamixel TTL **전달 경로**다. 카메라·정책·제어 루프·Dynamixel 패킷 생성은 노트북 Python 프로그램이 담당한다. OpenCR가 자체적으로 동작 안전 판단을 수행하거나 ROS 2를 실행한다고 해석하면 안 된다.

향후 OpenCR 펌웨어에 별도 저수준 제어·안전 기능을 구현한다면 현재 `usb_to_dxl` 경로와 **다른 프로토콜**이 되므로 상위 어댑터와 책임 경계를 별도로 설계한다. 현 실행에 추가 펌웨어 기능이 이미 있다고 가정하지 않는다.

## 전원과 배선 주의

- USB만으로 모터 전원을 공급하지 않는다.
- 전원 공급기와 모터 정격 전압·전류를 확인한다.
- 전원을 연결한 상태에서 신호선을 임의로 분리하지 않는다.
- 데이지체인 커넥터의 방향과 체결 상태를 확인한다.
- 모터가 기구적으로 걸린 상태에서 토크를 인가하지 않는다.
- 배터리와 모터 전원 분배는 실제 회로도와 부품 매뉴얼로 별도 검증한다.

## 배선 확정 전에 기록할 것

- 전원 공급기 모델과 출력
- 배터리 모델과 보호회로
- OpenCR TTL 3핀 사용 포트와 데이지체인 순서
- 모터 버스의 실제 순서
- 카메라 전원과 USB 연결
- 비상 전원 차단 방법

이 문서에 사진과 실제 회로도를 추가하기 전에는 확정되지 않은 배선 정보를 팀 표준으로 사용하지 않는다.

## 자유축 설계 시 추가 기준

모터 수가 늘면 연결 가능 여부보다 다음을 먼저 검증한다.

- 동시 구동 관절 그룹의 순간 전류와 전원 여유
- 움직일 때 무게중심이 지지면 밖으로 나가는지
- 관절 회전에 따른 케이블 비틀림과 최소 굽힘 반경
- 한 관절 통신 오류가 전체 구조를 끌어당기지 않는지
- 모터, 브라켓, 외장, 카메라를 개별적으로 교체할 수 있는지
- 서비스 패널과 커넥터에 손이 닿는지

외장은 모터를 가리는 장식으로만 설계하지 않고, 하중 경로와 정비 접근성을 함께 고려한 모듈로 만든다. 공통 체결 규격과 교체 가능한 외장 패널을 사용하면 연구용 기구를 제품형 디자인으로 발전시키기 쉽다.
