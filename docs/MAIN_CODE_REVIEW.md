# main 코드 리뷰와 정리
기준: notifyi/main c2e602b. 검토 범위: 두 모터 자세 반응의 Python 실행 경로, 의존성, 문서. config YAML과 3D 모델링 파일은 수정하지 않았다.

## 남아 있는 검증 및 다음 개발
- 실물 검증은 수행하지 않았다. Py 3.12/MP 0.10.13의 모델 준비 성공과 카메라 자세 인식의 정확도는 별개다. 이번 전체 설치 조합은 Pi에서 재확인이 필요하다.
- 해당 Pi는 약 2 fps였다. median_window=7과 평활화 때문에 실제 개입 지연은 3초보다 길 수 있다. 지속시간 설정 3초는 변경하지 않았다.
- 어깨·귀 가림이나 로봇 카메라 이동을 실제 녹화 영상으로 검증해야 한다. 지표는 의학적인 척추 각도 측정값으로 해석하지 않는다.
- 토크 유지 자세의 하중/온도·전도 방지와 위치 경계 부근의 실제 회전 경로는 아직 검증되지 않았다. 숫자 원주 차이만으로 기구의 안전한 경로가 증명되지 않는다.
- ID 2 zero=1에서 -30° 포즈를 수행하거나 복귀할 때 경계 통과가 발생하면 현재 코드는 차단한다. 위치 제어에서 경계가 걸리지 않는 zero/기구 설정을 실제로 확인한 뒤 별도 수정해야 한다. [ROBOTIS 제어 모드 설명](https://emanual.robotis.com/docs/en/dxl/x/2xl430-w250/#operating-mode11)
- ResponseTracker는 정상 자세 한 프레임으로 성공을 기록하고, good 판정이 시간 초과보다 먼저라 늦은 회복도 성공이 될 수 있다. 회복 뒤 unknown 구간이 유지시간에 포함될 여지도 있다. 로깅 개선은 별도 작업이며 이번에는 기존 로그 스키마를 유지했다.
- 개입 로그의 시작은 모터 큐 제출 성공 시점이다. 실제 모터 실행·도달의 확인 시점은 아니다.
- check_env는 import 검사다. MediaPipe SIGILL처럼 모델 초기화 때 발생하는 오류까지 성공으로 보장하지 않는다.

활성 import에서 보관 모듈 차단, 실제 두 모터 YAML 매핑·경계, 인식/출력 제한 분리, 오래된 관측, 모델 초기화 실패, 종료 중 zero·토크 해제 없음 및 실측 hold 지령 등을 하드웨어 없는 회귀 테스트로 확인한다.

검증 결과: 하드웨어 없는 Python 테스트 106개 통과. 직접 의존성 여섯 개의 Python 3.12 ARM64 바이너리 배포 파일 다운로드 성공. 종료 시 실측 hold 명령 실패는 로그와 종료 코드 1로 전달한다. Pi에서 이 전체 환경의 재설치·실물 움직임 검증은 별도다.
