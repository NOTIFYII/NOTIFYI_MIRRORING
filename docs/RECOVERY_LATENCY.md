# 자세 회복부터 복귀 지령까지의 지연 측정

`minwook`의 회복 지연 계측과 정상 회복 판정이다. 나쁜 자세의 3초 조건, 평활 필터,
모터 목표·속도·제어 순서는 유지하며 정상 회복만 별도 원시 관측으로 확인한다.
비교 측정에서 확인된 약 2.1 FPS를 바탕으로 추가 지연을 구분한다.

## 빠른 정상 회복 판정

기존 필터 기반 정상 판정에는 원시 정상 후보 이후 약 1.88초, 프레임 취득부터는
약 2.35초가 걸렸다. 새 recovery 설정은 원시 정상 판정 최소 2개의 서로 다른 프레임,
관측 시각 간 최소 0.3초, confidence ≥0.5를 요구한다. 프레임 간격이 1초를 넘거나,
관측이 처리 시각보다 1초 이상 오래되거나, 나쁨·미감지·낮은 신뢰도가 끼면 확인을
초기화한다. 같은 프레임을 제어 루프에서 여러 번 읽어도 횟수가 늘지 않는다.
FPS가 높으면 0.3초를 채우기 위해 2개보다 많은 정상 관측이 필요하다.

고정 포즈를 취소하려면 개입 접수 이후의 원시 정상 관측으로 확인해야 한다.
확인 플래그와 필터 관측은 같은 timestamp로 전달하며 오래된/다른 프레임의 확인은
사용하지 않는다. 미확인 필터 정상값만으로는 새 회복을 인정하지 않는다.
재무장과 기존 반응 로그에도 같은 확인을 적용하고, 나쁜 자세의 지속 판정은 기존
필터 입력·3초 정책을 유지한다. `recovery.enabled: false`면 이전 필터 기준으로 돌아간다.
실제 오검출률과 속도 개선은 아직 검증하지 않았다.

새 `[LATENCY] fast_recovery_latency`의 `capture_to_recovery_ms`를 확인한다.
기존 `perception_recovery_latency`는 필터 기준 비교용으로 계속 기록되므로 그 값이
여전히 2초 이상이어도 새 회복이 느리다는 뜻은 아니다. 복귀 지령에는 recovery_method와
`inference_to_recovery_ms`, `recovery_to_request_ms`를 추가해 사용한 기준을 구분한다.
세션의 `recovery_policy` 이벤트에 기준을 남기므로 이전 데이터와 무조건 합쳐 분석하지 않는다.

## 기록하는 단계

1. 카메라 스레드가 취득한 정상 자세 후보 프레임 시각.
2. 그 프레임의 추론이 끝난 시각.
3. 필터 뒤 정상 자세로 판정된 시각.
4. 제어 루프가 고정 포즈를 취소하고 복귀를 요청한 시각.
5. 달라진 복귀 Goal을 SDK로 전송한 시각.
6. 몸통 엔코더에서 중립 방향으로 12 ticks(약 1°) 이상 돌아온 것을 처음 읽은 시각.

실제 사용자가 자세를 고친 시각/센서 노출 시각은 알 수 없다. 따라서 표시되는 값은
**프레임 취득→지령 전송** 또는 **프레임 취득→엔코더 관측** 지연이며, 사람의 실제
교정 순간부터 잰 전체 반응시간이 아니다. 엔코더 관측은 기존 약 0.2초 폴링을 사용해
물리적 움직임 시작 시각을 정확히 측정하지 않는다. 추가 모터 읽기/지령은 하지 않는다.

## 이벤트와 해석

- `perception_recovery_latency`: 원시 판정에서 나쁜 자세→정상 후보→필터 정상 판정.
  모터 없는 실행에서도 확인할 수 있다.
- `recovery_latency_trial`: 실제 행동 요청이 제어 루프에 접수된 계측 에피소드 ID.
  물리적 피드백 도달을 증명하는 이벤트가 아니다.
- `return_requested`: 고정 포즈 취소와 복귀 판단.
- `return_command_sent`: 목표가 바뀐 복귀 지령의 SDK 전송 성공. GroupSyncWrite는
  각 모터의 수신/동작 성공을 보장하지 않는다(`physical_motion_verified: false`).
- `return_motion_observed`: 최근 실측 기준에서 몸통이 중립 방향으로 12 ticks 이상
  이동한 것을 읽음. 머리만 움직인 경우/기준 실측이 오래된 경우에는 기록하지 않는다.
- `recovery_latency_incomplete`, `recovery_motion_incomplete`: 실패·중단·새 요청 등으로
  단계가 완성되지 않음. 평균 계산에서 성공 또는 0초로 취급하지 않는다.

`capture_to_inference_ms`가 크면 추론/프레임 처리, `inference_to_filtered_good_ms`가
크면 필터가 정상 자세를 확정하는 데 추가 프레임이 필요했던 경우다.
`filtered_good_to_request_ms`는 제어 루프 반영, `request_to_command_ms`는 목표 생성과
전송까지의 소프트웨어 지연이다. `command_to_encoder_observation_ms`는 모터 이동과
폴링을 합친 값이다. 누락된 단계는 null이며, 음수 시간을 임의로 0으로 바꾸지 않는다.

로그는 기존 `data/runs/*.jsonl`에 남기고 제어 스레드는 이벤트를 메모리에 넣기만 한다.
파일 쓰기와 `[LATENCY]` 출력은 인식 루프/종료 처리에서 한다. 출력이 늦어져도 기록된
이벤트 시각은 원래 단조 시계 시각을 사용한다. 영상은 저장하지 않는다.

## 시험

앱 하나만 실행하고 동일한 위치·조명에서 먼저 모터 없이 시험한다.

```bash
cd ~/notiFYI
.venv-mp-pi3/bin/python -m src.main --no-preview --condition posture_trigger --camera /dev/video0
```

나쁜 자세를 유지하다가 정상으로 돌아오면 `[LATENCY] fast_recovery_latency`와
`perception_recovery_latency`를 함께 확인한다. 사람 미감지는 정상 회복으로 세지 않는다.
새 기준에서 짧은 정상 오검출로 회복을 인정하지 않는지도 시험한다.
모터 지연은 기존 안전/시야 조건을 확인한 뒤 같은 명령에 `--move`를
붙여 시험한다. 복귀 지령·엔코더 이벤트는 실제 행동 접수된 시도에서만 생성된다.
실제 사람이 회복한 시각을 포함한 전체 지연은 별도 외부 영상/동기화 표식이 필요하다.

## 빠른 회복 로그가 없을 때

최신 버전·enabled 상태에서도 로그가 없을 수 있다. 원시 정상값이 연속되지 않았거나,
프레임 나이/간격이 제한을 넘었을 수 있다. 또한 미감지로 이전 나쁨→정상 계측 구간이
끊기면 이후 정상 회복 확인이 성공해도 그 구간의 fast 지연 로그는 생성하지 않는다.
로그 부재만으로 복귀 기능 실패라고 결론 내리지 않는다.

앱·자동 인식 서비스 등 카메라 점유를 종료한 뒤 모터 없는 진단을 실행한다:

```bash
.venv-mp-pi3/bin/python scripts/diagnose_recovery.py --camera /dev/video0 --seconds 30
```

`raw`, `conf`, `age_ms`, `gap_ms`, `good_frames`, `confirmed`, `reason`을 확인한다.
`confirmed=True`인데 fast 로그가 없으면 계측 구간의 이전 나쁨/미감지 여부를 먼저
검토한다. `raw_slouch` 등은 원시 판정 문제, `stale_frame`은 관측 나이,
`low_confidence`는 신뢰도, `frame_gap_reset`은 관측 간격 문제다.
이 도구는 설정·회복 기준·모터 동작을 변경하지 않는다.
