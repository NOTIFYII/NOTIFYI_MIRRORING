# Notifyi 조립 검토 화면

조립 검사 표시는 브라켓별로 `판 홀 정렬 / 정적 간섭 / 회전 간섭 / 배선 여유`를 분리한다. 제공 STEP에서 확인한 +Z면 판 홀 정렬과 특정 `판 고정 + A축 포크` 예제의 ±30° 간섭만 해당 브라켓에 적용한다. 다른 축·체결 방향에는 결과를 전파하지 않고 `미검증`으로 남긴다. 이 표는 새로운 충돌 계산기나 실물 구동 허가가 아니다.

장비 상태의 `화면상 케이블 직선거리`는 연결된 3P 케이블의 화면상 두 소켓 중심 사이 유클리드 거리를 mm로 환산한다. 소켓 중심은 STEP 부품 외접 범위를 기준으로 수동 배치된 근사점이며, 배선 경로·굽힘 반경·움직임 여유·실제 케이블 길이는 계산하지 않는다. 180 mm를 넘는 경우도 참고 경고일 뿐, 실물 적합·부적합 판정이 아니다.

`현재 조립안 부품 수량`은 화면에 존재하는 모터 하우징·브라켓·케이블·OpenCR·노트북 수를 표시하고 CSV로 내보낸다. 브라켓 판과 포크 양쪽 또는 케이블 양 끝이 연결된 경우만 연결 완료로 센다. 이 수량표는 구매 목록이나 검증된 조립 공정표가 아니며, 나사·스페이서·실물 재고는 포함하지 않는다.

실물 모터 읽기 전용 동기화와 조립판의 남은 개발 과제는 [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md)에 단계별 완료 조건으로 정리했다.

제공 STEP의 볼트 홀과 배치 예제의 간섭을 별도로 계산했다. 결과와 한계는 [CAD_FIT_AUDIT.md](CAD_FIT_AUDIT.md)에 있다. **현재 2모터 예제는 +Z면 판 홀 4개가 정렬되지만 A축 ±30°에서 형상이 겹쳐 구동 가능한 설계가 아니다.**

기본 3D 장면은 탁상용 로봇을 놓는 책상과 그 위의 노트북·OpenCR·모터로 시작한다. **상판 윗면이 장면 Y=0**이며, 부품 위치 입력의 Y 값도 이 면을 기준으로 한다. 책상은 저장 JSON에 포함되지 않는 시각적 배경이며, 충돌·하중·책상 치수를 검증하는 형상이 아니다. 이전 버전의 브라우저 저장본·JSON은 높이 차이 1.58만큼 한 번 변환해 읽는다. 브라우저의 예전 저장본은 남기고 새 좌표계 저장본을 별도 키에 저장한다. 빈 브라켓과 TTL 케이블은 처음에는 작업면에서 숨기고, 부품 목록에서 선택하거나 연결·이동하면 표시한다. 기존 브라우저의 조립 배치는 유지된다. 노트북은 실제 치수 CAD가 아닌 화면용 프록시다.

사용자가 제공한 `2XL-430.stp`를 원본 배율 그대로 `assets/2XL-430.step.stl`로 변환해 표시한다. 이 STEP는 이전에 받은 `2XC-430.stp`와 SHA-256까지 동일하므로 **2XL 전용 CAD인지 독립 검증된 것은 아니다.** 두 모델의 공칭 외형은 모두 `36 × 46.5 × 36 mm`이고, 이 조립 STEP의 혼·아이들러 돌출부까지 포함한 외접 범위는 약 `40.90 × 46.50 × 40.90 mm`다. 이전의 폭·깊이를 강제로 줄인 프록시 대신 실제 STEP 크기를 유지했다. 추가로 `EF25-F14.stp`를 브라켓 자산으로 변환하고, [ROBOTIS 공식 OpenCR-Hardware](https://github.com/ROBOTIS-GIT/OpenCR-Hardware)의 `OpenCR_REVH.stl`을 추가했다. 현재는 5개 모터 조립을 확정하지 않고, 각 부품을 1개 이상 배치한 뒤 필요한 만큼 복제해 조립 구성을 탐색한다.

조립 화면의 **체결** 도구에서는 모터 축과 브라켓 연결점만 표시한다. 브라켓의 판을 먼저 선택하면 연결 가능한 모터 본체 체결면만 나타난다. **배치·회전** 도구에서는 체결 윤곽을 숨기고 선택한 부품의 이동·회전 핸들만 표시한다. 두 도구를 전환하면 진행 중인 연결 선택은 취소된다.

부품을 선택하면 속성 패널의 **본체 배치 각도**에서 X/Y/Z축별 `−90°`, `0°`, `90°`를 바로 적용할 수 있다. 다른 배치 방향은 `기타`에 `−180°~180°` 값을 입력한다. 세 축의 값은 서로 독립적이며 브라우저 저장·JSON에도 유지된다. 이 값은 부품 본체의 고정 배치 방향(`rot`)이고, **동작 확인**에서 드래그·길게 누르기로 연속 변경하는 모터 A/B 관절값(`joints`)이나 실제 구동 한계가 아니다. 결합으로 위치가 고정된 부품은 배치 각도를 수정할 수 없다.

배치 회전은 화면의 월드 X→Y→Z 순서로 합성된다. 현재 A/B 관절의 `−90°~+90°` 제한은 화면에서 모델이 지나치게 돌아가지 않도록 한 **미리보기 범위**일 뿐이다. ID별 운용 범위나 과부하·충돌 안전 범위로 쓰면 안 된다. 체결 안내에는 `미검증`, `체결 불가`, `부분 확인 / 간섭 확인`을 구분한다. `부분 확인`은 +Z면 판 홀 네 개의 도면상 정렬만 뜻하며, 전체 조립이나 회전 경로의 안전 판정이 아니다.

### 실제 모터와 동기화할 때

현재 가능한 것은 삼성 노트북에서 수동 스캔한 위치·토크 ON/OFF·오류를 **마지막 측정 시점**으로 표시하는 것까지다. 지속적인 각도 동기화나 화면에서 실물 모터로 명령을 보내는 기능은 없다. 다음 순서로 분리해 개발한다.

1. **읽기 전용 연속 동기화:** 삼성 노트북에서 시리얼 포트를 소유한 단일 프로세스가 ID별 현재 위치와 오류를 주기적으로 읽어 게시한다. 메인 제어가 실행 중이면 별도 스캐너가 같은 포트를 열지 말고 메인 제어 프로세스가 값을 게시한다. 화면은 값의 타임스탬프, 통신 단절, ID 미배정을 표시한다. 이 단계는 토크와 목표 위치를 쓰지 않는다.
2. **실물 구동 전 검증:** 각 2XL 하우징의 A/B축↔물리 ID·부호·zero를 실물에서 확인하고, 브라켓·케이블을 포함한 전 가동 구간 간섭 및 ID별 기계적 한계를 측정한다. 지금 제공된 조립 예제는 ±30°에서 간섭이 확인되어 구동 후보가 아니다. 정지·통신 단절·과부하 시의 절차, 단일 포트 소유권, 토크 해제 시 낙하 위험도 시험한다.
3. **제한된 구동 연동:** 별도 승인된 운용 범위 안에서만 모터 담당 프로세스가 명령을 실행하고, 화면에는 요청값과 실제 읽은 위치를 구분해 표시한다. 브라우저의 미리보기 각도나 JSON 값이 모터 명령으로 자동 전송되지 않도록 한다.

즉, 읽기 전용 실시간 표시는 현재 하드웨어 연결과 ID 매핑을 확인하면 다음 구현 단계에서 가능하다. 실물 구동 연동은 날짜를 약속할 수 없고 위 안전 검증을 통과한 뒤에만 진행한다.

## 실행

3D 메시를 브라우저의 WebGL로 읽는다. 설정 파일의 ID 매핑과 **이 컴퓨터에 시리얼 장치 경로가 있는지** 함께 보려면 읽기 전용 로컬 서버로 연다. 맥에서 처음 실행할 때는 레포 루트에서 전용 Python 환경과 서버 의존성(`PyYAML`)을 준비한다. 이미 `.venv`가 있으면 첫 두 줄은 건너뛴다.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install 'PyYAML==6.0.3'
.venv/bin/python tools/digital_twin/serve.py --port 18766
```

그 다음 **같은 맥의 브라우저**에서 다음 주소를 연다. 종료는 서버 터미널에서 `Ctrl+C`를 누른다. 포트가 사용 중이면 `--port 18767`처럼 바꾸고 브라우저 주소도 같은 포트로 맞춘다. 서로 다른 포트는 브라우저 자동 저장 영역도 서로 다르다.

`http://127.0.0.1:18766/`

### 브라우저 조립·배선 회귀 검사

Playwright Chromium이 설치된 컴퓨터에서 아래 검사를 실행하면 로컬 서버를 임시로 열고 닫으며 실제 브라우저에서 일곱 가지를 확인한다: 체결 후 모터의 버튼·드래그 회전, OpenCR의 여러 TTL 포트 연결, OpenCR→모터→모터 데이지체인 배선, 브라우저 자동 저장·JSON 내보내기·불러오기, 체결 윤곽과 배치·회전 핸들의 분리, Y=0 책상 좌표와 예전 저장본 복원, 배치 각도와 관절 동작의 분리. 실물 모터에는 접근하지 않는다.

```bash
PLAYWRIGHT_MODULE="$(npm root -g)/@3xhaust/oh-my-design/node_modules/playwright" node --test tests/test_digital_twin_browser.cjs
```

다른 위치에 Playwright를 설치했다면 `PLAYWRIGHT_MODULE`에 그 모듈 경로를 지정한다. 코드·저장 포맷·브라켓별 검증 범위·화면 거리·부품 수량 단위 검사는 `node --test tests/test_digital_twin_kinematics.js tests/test_digital_twin_project_state.js tests/test_digital_twin_fit_audit.js tests/test_digital_twin_cable_measure.js tests/test_digital_twin_assembly_bom.js`로 실행한다.

### 조립 작업 저장·이동

부품의 개수·위치·회전, 모터 A/B 축 각도와 실물 ID 배정, 브라켓 결합, 케이블 연결은 변경 후 같은 브라우저의 로컬 저장소에 자동 저장된다. 같은 주소로 다시 열면 마지막 작업을 복원한다. 저장 상태와 JSON 입출력은 **장비 상태** 화면에서 확인한다. 브라우저 데이터 삭제, 시크릿 모드, 다른 브라우저·포트·컴퓨터에서는 자동 복원이 되지 않을 수 있다.

맥과 삼성 노트북 사이에 작업을 옮기거나 백업하려면 **JSON 내보내기**로 파일을 받은 뒤 다른 화면에서 **JSON 불러오기**를 누른다. 파일의 형식·연결 관계를 검사한 뒤 적용하며, 잘못된 파일은 현재 작업을 덮어쓰지 않는다. JSON에는 조립 시뮬레이션만 담고 실물 모터 응답, USB 연결 상태, LED, 실제 각도는 담지 않는다. 자동 저장은 기기 간 동기화가 아니므로 다른 컴퓨터에서 수정한 내용은 JSON으로 다시 옮겨야 한다.

이 서버는 `127.0.0.1`에만 바인딩되며 시리얼 포트를 **열지 않고**, 토크·목표 위치 등 명령을 **보내지 않는다**. 포트가 이미 사용 중이면 `18767` 같은 다른 포트를 사용한다. 삼성 노트북의 `/dev/ttyACM0`을 보려면 서버도 삼성 노트북에서 실행해야 한다. 맥에서 실행하면 맥의 장치 경로만 검사한다. 단순 `http.server`로 열면 3D는 볼 수 있지만 장비 상태 API는 제공되지 않는다.

화면의 노트북은 외형 프록시다. 노트북→OpenCR Micro‑B USB 선은 현재 작업 배선의 **계획 표현**이지 USB가 실제로 연결됐음을 인증하는 표시가 아니다. 장치 경로가 존재해도 보드가 OpenCR인지, 외부 전원이 들어왔는지, 모터가 응답·이동했는지는 알 수 없다.

### 연결 표시를 확인하는 방법

화면에는 서로 다른 세 상태가 따로 표시된다.

- **화면 배선:** 3D에서 연결한 케이블 수. 물리적 연결 여부를 뜻하지 않는다.
- **USB 장치 경로:** 이 서버가 실행 중인 컴퓨터에서 설정된 `/dev/ttyACM0`가 존재하는지. 경로가 있어도 OpenCR인지는 미확인이다.
- **모터 응답:** 삼성 노트북에서 아래 읽기 전용 스캔을 *수동*으로 실행했을 때 설정된 57600bps에서 응답한 ID. 검사 후 15초가 지나면 현재 연결 상태가 아닌 ‘마지막 검사’로 바뀐다.

ID별 표에는 `config/joints.yaml`의 **zero position**(ID 2~7: 1034, 3059, 2040, 12, 38, 3039 ticks)과 수동 스캔에서 읽은 `Torque Enable`(0=해제, 1=인가), 현재 위치 tick을 나란히 표시한다. ID 1·8은 현재 비구동으로 zero 값이 설정되지 않았다. `Torque Enable`은 실제 토크 크기(N·m)나 부하량이 아니다. 스캔하지 않았거나 이전 버전의 결과 파일이면 토크·현재 위치는 `미확인`으로 표시하고, 새 스캔을 하더라도 이는 해당 시점의 기록이지 실시간 값이 아니다. 이 화면은 토크를 켜거나 모터를 움직이지 않는다.

**동작 확인** 화면에서 모터 몸체를 선택한 뒤 **실물 모터 ID 배정**에서 A/B축 ID를 각각 선택한다. 어느 ID가 어느 2XL 하우징의 축인지 아직 검증되지 않아 기본값은 모두 `미배정`이며, 한 ID를 두 축에 중복 배정할 수 없다. **장비 상태** 화면의 모터 정보 카드에는 배정된 ID의 zero와 마지막 수동 스캔의 토크 0/1이 표시된다. 이 배정은 화면 표시와 JSON 저장에만 적용되며 `config/joints.yaml`이나 실제 모터 설정을 바꾸지 않는다. 기존 JSON은 ID 미배정 상태로 그대로 열 수 있다.

메인 로봇 제어를 먼저 종료하고 시리얼 포트를 쓰는 다른 프로그램도 닫은 뒤, 삼성 노트북의 레포 루트에서 실행한다. 이 스캔은 토크·목표 위치를 쓰지 않는다.

```bash
python scripts/scan_dynamixel.py --port /dev/ttyACM0 --baud 57600 --proto 2.0 --status-file data/connection_status.json
```

결과 파일은 Git에서 제외된다. 스캔 후 위 화면을 열어 두면 상태가 자동 갱신된다. 이 방식은 **마지막 검사 결과**이며 메인 로봇 프로그램 실행 중의 실시간 모터 연결 확인은 아니다. 그 단계에서는 시리얼 포트를 한 프로그램만 사용하도록 메인 제어 루프가 모터 응답을 읽기 전용 채널로 게시해야 한다.

맥북에서 삼성 노트북의 화면·상태를 보려면 삼성 노트북에서 `serve.py`를 실행하고, 연결 가능한 SSH 경로를 이용해 맥북에서 `ssh -L 18768:127.0.0.1:18766 wookmin@172.17.221.147`로 터널을 연 뒤 `http://127.0.0.1:18768/`에 접속한다. 이 명령은 예시이며 삼성 노트북의 IP·SSH 연결이 살아 있어야 한다. 현재 맥북의 `127.0.0.1:18767`은 맥북 자체 서버라 삼성 노트북의 장치를 볼 수 없다.

## 할 수 있는 것

- 첨부 STEP를 배율 변경 없이 변환한 `2XL-430.step.stl` 메시 표시
- 실제 STEP에서 변환한 EF25-F14 브라켓 표시
- DXL TTL 3P 케이블 프로토타입 표시
- ROBOTIS 공식 OpenCR REVH 보드 메시 표시
- 부품별 최소 1개 유지
- 부품 목록의 `＋`로 인스턴스 추가, `−`로 마지막 인스턴스 삭제
- 화면 상단의 **조립 / 배선 / 동작 확인 / 장비 상태**로 작업을 전환한다. 3D 조립판이 작업 화면을 채우며 부품 목록은 왼쪽, 선택 부품의 속성은 오른쪽에 나타난다
- 3D 메시의 몸체를 클릭해 부품을 선택한다. **조립**에서 이동·회전 모드를 선택하고, 선택 부품 위의 X/Y/Z 화살표 또는 회전 링을 드래그한다. 화살표·링에 초점을 맞춘 뒤 방향키로도 조작할 수 있다. 정확한 수치는 속성의 접힌 입력란에서 지정한다
- 빈 공간 드래그로 시점을 회전하고, Shift/마우스 오른쪽 드래그로 시점을 평행 이동한다. 휠은 확대·축소, **전체 보기**는 배치된 모터 쪽으로 화면을 맞춘다. 상단에서 실행 취소·다시 실행이 가능하다
- 2XL430의 두 독립 출력축을 **A(+Z 혼↔−Z 아이들러)**, **B(+X 혼↔−X 아이들러)**로 구분. A/B는 화면용 이름이며 실제 다이나믹셀 ID가 아님
- 한 축의 출력 혼과 반대편 아이들러를 **같은 포크 체결쌍**으로 취급한다. 브라켓 판은 다른 2XL의 본체에 붙는다. 따라서 브라켓 한 개가 닿는 위치는 출력 혼·아이들러·본체 판의 세 곳이고, 연결되는 2XL 하우징은 두 개다. 모터 하우징 하나에 EF25-F14 브라켓을 축별로 하나씩, 총 두 개까지 결합 가능
- 출력축은 첨부 STEP 안의 혼·아이들러 위치를 기준으로 원형 윤곽선 표시. 클릭 윤곽의 반지름은 근사치
- 기본 브라켓 기준은 **본체 고정 · 축 모터 이동**이다. 제공 STEP상 홀 정렬이 확인된 본체 +Z면에 브라켓 판을 배치하고, 포크를 다른 모터 A축에 연결하는 **정적 체결 예제**를 제공한다. 이 예제는 ±30° 회전 간섭이 있어 실제 구동에 사용하면 안 된다. 기존 저장 프로젝트에서 기준 설정이 없으면 종전의 **축 고정 · 본체 이동** 방식으로 읽어 기존 동작을 유지한다
- 브라켓을 선택하면 세 접촉부의 연결 상태와 기준을 볼 수 있다. 양쪽 연결을 마친 뒤에는 기준 변경을 막는다. 판 연결은 본체 네 측면에서만 새로 선택할 수 있다. 윗면/아랫면은 대응 홀 패턴이 없어 새 결합을 막았고, 이전 JSON에 저장된 결합은 제거하지 않고 경고한다. 다른 세 측면은 아직 체결·간섭 미검증이다
- 모터 본체의 X/Y/Z 배치 회전과, 선택 모터의 A/B 축 회전(화면상 ±90°)을 별도로 조작한다. A/B 축은 정·역방향 버튼을 누르고 있는 동안 연속 회전하고 짧게 누르면 1° 움직인다. 본체 고정 방식에서는 포크에 연결된 모터 본체가, 축 고정 방식에서는 판에 연결된 모터 본체가 움직인다. **실제 모터 제어 또는 센서 각도 반영은 아니다**
- 체결 후 상대 모터를 선택해 **동작 확인** 모드에서 몸체를 좌우로 드래그하거나 `−90° / 0° / +90°` 자세 버튼으로 축 각도를 바꿀 수 있다. 브라켓의 혼·아이들러·판 연결은 유지되고, 변경한 각도는 조립 JSON에 저장된다. 기준 모터를 포함한 전체 조립체를 눕히려면 **조립** 모드에서 기준 모터를 선택하고 회전 핸들로 배치 방향을 바꾼다. 이는 관절 회전과 다른 조작이다. 제공 +Z/A 예제는 ±30°에서 이미 CAD 간섭이 있으므로 `±90° 눕혀보기`는 안전한 실제 동작을 의미하지 않는다
- 브라켓을 선택해 연결 해제할 수 있고, 이미 결합된 판 또는 모터 본체의 연결면을 다시 클릭하면 판만 해제된다. 같은 축의 반대편 윤곽선은 사용 중으로 표시하지만 다른 축은 계속 사용 가능하다
- 연결 선택 중 `Esc`로 취소. 부품이 여러 개면 목록의 `#1`, `#2` 등으로 개별 선택 가능
- STEP의 `S3B-EH` 헤더 및 `EHR-3` 플러그 부품 두 쌍을 근거로 **서로 직교하는 −X/−Z 측면의 3P 연결부**를 각각 독립된 윤곽으로 표시. 호버하면 강조·이름이 나타나고, 윤곽을 직접 눌러 선택한다. 윤곽은 해당 부품 외접 범위의 근사이며 실제 삽입면·케이블 출구 방향은 미검증
- OpenCR의 TTL 1/2/3은 공식 REVH STEP의 `JST_B3B_EH_A` 하우징 외접 범위에서 메시 중심을 뺀 좌표로 표시한다. USB Micro‑B도 REVH STEP의 하우징 범위에 배치했다. RS-485 4핀 3개는 배선 후보가 아니다. TTL 3개는 같은 데이터·전원 버스를 공유하며 독립 제어 채널이 아니다
- 3P 소켓을 클릭한 동안 다른 모터 3P 또는 빈 OpenCR TTL 3P만 윤곽으로 표시한다. 축·USB 등 불가능한 연결점은 화면에서 숨긴다
- `config/robot.yaml`, `config/joints.yaml`에서 ID 2~7의 관절명·zero tick, 유휴 ID 1·8을 읽어 표시한다. 2XL 하우징별 두 ID의 실제 쌍은 아직 매핑되지 않았다
- USB 장치 경로는 서버가 실행되는 호스트에서 3초 간격으로 확인한다. 모터 응답은 별도 수동 스캔의 최근 결과만 표시한다. 실제 보드 ID, 전원 전류, 모터 각도·동작, 보드 LED는 이 페이지에서 읽지 않는다
- 케이블은 모터 3P ↔ 다른 모터 3P 또는 OpenCR TTL 1/2/3 조합만 허용하며, 이미 사용 중인 소켓은 중복 연결할 수 없다
- **배선** 모드로 들어가면 모터의 두 3P 소켓과 OpenCR TTL 1/2/3이 보이는 3P 시점으로 자동 전환한다. 소켓 하나를 누른 뒤 호환 소켓만 선택해 케이블을 연결한다. 연결할 때 빈 TTL 케이블 부품이 없으면 자동으로 하나 추가한다(최대 64개). 노트북↔OpenCR USB 선은 별도이며 TTL 케이블 개수를 차지하지 않는다
- 브라켓의 포크 중심을 선택 축의 혼·아이들러 중심에 맞추고, 판 중심을 본체 측면에 맞춰 배치한다. +Z면 판 홀 정렬 및 0.5 mm 간격에서의 정적 체적 간섭은 제공 STEP으로 계산했다. 그러나 해당 예제의 ±30° 회전 간섭이 확인돼 화면에서 회전할 수 있어도 실제 구동 가능성을 보증하지 않는다. 나사·스페이서·공차는 미검증
- DXL 3P와 OpenCR TTL은 같은 TTL 멀티드롭 버스의 포트이며 특정 ID와 일대일 대응하지 않음
- 전기 포트와 기계 체결 홀, 같은 모터 내부 포트, OpenCR TTL끼리의 연결 등 불가능한 조합은 연결되지 않음
- 2XL430 실제 케이블은 기본 구성품인 X3P JST-JST 케이블을 기준으로 표시하며, [ROBOTIS 903-0224-000](https://www.robotis.com/shop/item.php?it_id=903-0224-000)은 XL-320 전용으로 호환 부품으로 확정하지 않음
- 연결된 부품은 이동 핸들을 잠근다. 다른 위치로 옮기려면 속성의 `선택 부품 연결 해제`를 먼저 사용한다
- `선택 보기`로 선택 부품을 화면 중심에 맞춘다
- 모터 ID·zero·마지막 토크 상태는 모델 위에 겹치지 않도록 3D 화면 우상단 고정 정보 영역에 표시한다. 뒤/아래 면을 확인할 때도 어둡게 사라지지 않도록 보조 조명을 사용한다
- 정면·측면·상면·하면 카메라
- 선택 부품 초기 위치 및 전체 초기 배치 복구
- 자동 카메라 회전
- 기존 2D 조립 스키매틱은 `assembly-2d.html`에서 별도 확인

### 첨부 STEP에서 읽은 연결부 기준

STEP 조립 좌표(mm)는 메시 로더에서 외접 범위의 중심 `(0.45, 0, 0.45)`를 뺀 뒤 화면에 사용한다. 다음 값은 조립 트리의 개별 부품 **외접 범위 중심**이지 소켓 접점이나 볼트 홀의 계측 좌표가 아니다.

| CAD 부품 | 원본 STEP 중심 (x, y, z) mm | 화면 표시 기준 |
| --- | --- | --- |
| `S3B-EH` / `EHR-3` 첫 번째 쌍 | 약 `(-12.6, 1.2, -5.4)` / `(-14.5, 3.85, -5.4)` | −X 면 3P 연결부 |
| `S3B-EH` / `EHR-3` 두 번째 쌍 | 약 `(-5.4, -1.2, -12.6)` / `(-5.4, -3.85, -14.5)` | −Z 면 3P 연결부 |
| A축 혼 / 아이들러 | `(0, 12, 17.9)` / `(0, 12, -15.8)` | +Z / −Z 원형 윤곽 |
| B축 혼 / 아이들러 | `(17.9, -12, 0)` / `(-15.8, -12, 0)` | +X / −X 원형 윤곽 |

3P 클릭 윤곽은 플러그 외접 범위를 표면에 투영한 것으로, 케이블이 실제로 들어가는 방향이나 실제 소켓의 개구면을 보증하지 않는다. 현재 STEP 조립에는 플러그 하우징이 함께 포함돼 있으므로, 실물 모터에 케이블이 꽂혀 있지 않을 때의 외형과 일부 다를 수 있다.

## 현재 범위와 한계

현재 페이지는 조립 UX와 배치 후보를 확인하기 위한 시뮬레이션 전용이다. [ROBOTIS 2XL430 공식 문서](https://emanual.robotis.com/docs/en/dxl/x/2xl430-w250/)는 두 독립축, TTL 3P 통신, 프레임/혼 조립 및 도면을 제공한다. STEP 조립 트리에서 헤더와 플러그의 외접 범위를 읽어 3P 연결부 윤곽을 −X/−Z 두 면에 옮겼다. 혼과 아이들러의 중심은 STEP 컴포넌트의 외접 범위를 기준으로 조정했다. 단, 제공 파일은 앞서 받은 2XC STEP와 완전히 같으므로 실제 2XL 외형과 동일한지, 실제 3P 케이블의 삽입 방향이 어느 쪽인지 확인이 필요하다. [OpenCR 공식 핀 배치](https://emanual.robotis.com/assets/images/parts/controller/opencr10/opencr_pinout.png)에서는 TTL 3개가 보드 긴 변에서 RS-485 3개 바로 옆에 있다. OpenCR TTL 윤곽은 REVH STEP의 `JST_B3B_EH_A` 부품 **외접 범위**를 기준으로 배치했지만, 실제 소켓 개구면이나 케이블 삽입 방향을 계측한 값은 아니다. +Z면의 볼트 홀 정렬과 한 배치의 간섭만 계산했으며 나머지 조립이나 케이블의 실물 체결 가능성을 증명하지 못한다.

로컬 브라우저에서 모터 3P 선택 → 호환 포트만 표시 → OpenCR TTL 1 선택 → 케이블 경로 생성과, 모터 #1 A축 → 브라켓 #1 → 모터 #2 A축 → 브라켓 #2 → 모터 #3 연결을 확인했다. 첫 모터 A축을 45° 회전시키자 셋째 모터의 화면상 위치와 방향도 함께 달라졌다. 이는 UI 동작 검증이지 실제 조립 또는 모터 구동 검증은 아니다. EF25-F14와 본체 +Z면의 네 홀 중심은 STEP상 정렬됨을 계산했지만 실물 공차, 나사, 스페이서, OpenCR 포트 하우징의 삽입 방향, 케이블 굽힘 반경은 아직 검증되지 않았다. 3P 윤곽은 CAD 부품 외접 범위를 수동으로 투영한 것으로 실제 소켓 입구가 아니다.

1. 제조사 제공 2XL 전용 STEP와 현재 첨부 STEP가 동일한지 대조하고 실물 사진으로 소켓 방향 확인
2. 출력축·혼·브라켓·케이블·OpenCR 기준축 표시
3. 모터 케이블 연결 지점과 실제 포트 방향 정합
4. 브라켓 홀 패턴과 실제 연결면 정합
5. OpenCR 전원·DYNAMIXEL·USB 포트의 보드 방향 정합
6. 실제 ID 하나의 ticks를 read-only로 연결
7. 한 축의 실제 회전과 3D 모델 회전 비교
8. 검증 후에만 ID 2~7 조립 및 OpenCR 배선 추가

OpenCR의 입력·출력과 Notifyi 연결안은 [`docs/OPENCR_IO_MAP.md`](../../docs/OPENCR_IO_MAP.md)에 정리했다.

현재 브라우저는 모터에 명령을 보내지 않는다. 실제 연결 단계에서도 먼저 read-only로 두고, 쓰기 명령은 별도 안전 게이트 뒤에 둔다.
